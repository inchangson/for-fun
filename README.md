# Tokyo, October

2026년 10월 1–7일 도쿄 여행을 위한 정적 사이트. 홈, 날짜별 7개 페이지, 맛집·쇼핑 주소록, 준비물 체크리스트, 출처 페이지로 구성합니다. Vanilla JS + Vite + Leaflet을 사용합니다.

## 실행

```sh
npm ci
npm run dev
```

표시되는 localhost 주소로 엽니다. 저장소 루트에서 `python -m http.server`를 실행하지 마세요. 루트에는 로컬 비공개 데이터가 있을 수 있습니다. 개발 서버는 `site/`만 제공하며, 배포는 아래의 `dist/`만 사용합니다.

```sh
npm run build
npm run preview -- --port 4173
```

정적 호스팅에는 `dist/` 내용만 업로드합니다. Railway와 서버, API 키는 필요하지 않습니다. 해시 URL을 사용하므로 별도의 서버 라우팅 설정 없이 `/for-fun/#/days/2026-10-02` 같은 하위 경로도 지원합니다. 실제 운영은 HTTPS가 필요합니다. 현재 작업에는 외부 배포를 포함하지 않습니다.

## 내용 수정

### Netlify 배포

기존 Netlify 사이트를 그대로 사용할 수 있습니다. 저장소 루트의 `netlify.toml`에 빌드 명령 `npm run build`, 배포 디렉터리 `dist`, Node 22를 설정했습니다. Netlify의 Base directory는 저장소 루트로 둡니다. `site/`를 배포 폴더로 지정하지 않습니다.

Netlify에 비밀번호나 복호화 키를 등록하지 않습니다. 비공개 내용을 바꾸면 로컬에서 `npm run encrypt` 후 변경된 `site/public/private.enc.json`을 공개 코드와 함께 커밋·푸시합니다. Netlify는 이미 암호화된 파일을 복사하여 배포합니다. `.private/` 없이 빌드 가능하며 방문자가 입력한 비밀번호로 브라우저에서 해독합니다.

`VITE_PASSWORD` 같은 변수를 만들지 마세요. `VITE_` 변수는 브라우저 코드에 포함될 수 있습니다. 빌드 환경에서 새로 암호화하려는 경우에만 별도의 서버 측 비밀값 전달 설계가 필요하며, 현재 구조에는 필요하지 않습니다.

### 공개·비공개 데이터 편집

- `site/src/trip.json`: 공개 장소, 날짜별 순서, 식당 후보, 준비물, 공식 출처. 상세 시간·숙소·항공·개인 메모를 넣지 않습니다. 미확정 사항은 확정 예약처럼 표시하지 않습니다.
- `site/src/photos.json`: Wikimedia 이미지 URL, 원본 fallback URL, 저작자·라이선스. 사진은 직접 링크하며 다운로드하지 않습니다. 외부 서비스가 응답하지 않으면 대체 안내가 표시됩니다.
- `.private/details.json`: 로컬에서만 관리하는 비공개 원문. 키는 공개 데이터의 `privateRef`에 대응하는 32자리 임의 hex ID입니다. 신규 ID는 `node -e "console.log(require('node:crypto').randomBytes(16).toString('hex'))"`로 만들 수 있습니다.

비공개 레코드의 형식:

```json
{
  "불투명한_ID": {
    "title": "상세 일정",
    "lines": ["개인 상세 시간이나 예약 메모"],
    "links": [{"label": "예약 확인", "url": "https://example.com/private-reservation"}]
  }
}
```

원본 엑셀은 Downloads에 그대로 두었으며 추출한 원문은 `.private/source.json`에 보존했습니다. 초안의 개인 메모는 암호화된 기록으로만 사이트에서 볼 수 있습니다. 해당 로컬 파일은 Git과 배포에 포함하지 않으므로 별도로 안전하게 백업하세요. 공개 저장소 복제본만으로는 비공개 원문을 편집할 수 없습니다.

공개 데이터만 수정할 때는 `npm run build`로 충분합니다. 비공개 내용을 수정할 때는 반드시 다시 암호화합니다.

```sh
npm run encrypt
npm run build
```

처음 암호화할 때 비밀번호가 없으면 강한 임의 비밀번호를 생성해 `.private/password.txt`에 권한 600으로 저장합니다. 명령 출력에는 노출하지 않습니다. 이후 `npm run encrypt`는 이 로컬 파일을 사용합니다. 브라우저에는 비밀번호를 저장하지 않습니다.

직접 정한 비밀번호로 암호화하려면 아래 명령에서 8자 이상의 비밀번호를 숨김 입력합니다. 명령행 인수나 공개 환경 변수로 비밀번호를 넘기지 마세요. `--prompt`로 재암호화하면 로컬 비밀번호 파일도 함께 갱신되어 다음 암호화에 같은 비밀번호를 사용합니다.

```sh
npm run encrypt -- --prompt
npm run build
```

비밀번호를 변경하면 새 암호문으로 재배포해야 합니다. 이미 배포된 과거 암호문이나 열람·복사된 정보를 회수할 수는 없습니다.

## 보호 방식

`<private-detail>` 요소에는 식별자만 들어갑니다. 원문은 PBKDF2-SHA-256 600,000회, 임의 salt, AES-256-GCM의 임의 IV로 암호화하여 `site/public/private.enc.json`에 저장합니다. 빌드 스크립트만 로컬 원문을 읽습니다. 공개 지도에는 관광지만 표시하고 실제 숙소나 개인 이동 경로는 넣지 않습니다.

상단 토글을 켜면 비밀번호 입력 후 모든 상세 정보가 해제됩니다. 사이트 내 이동 동안만 메모리에서 유지하며 OFF·새로고침·페이지 이탈·뒤로가기 캐시 복원 때 다시 잠깁니다. 닫힌 입력창의 대기 중 복호화도 취소합니다. 원문 텍스트는 HTML로 실행하지 않고, HTTPS 링크만 생성합니다. 비밀번호·키·원문은 브라우저 저장소나 로그로 보내지 않습니다. 메모리의 물리적 삭제나 악성 확장 프로그램으로부터의 보호를 보장하지 않습니다.

지도 배경은 OpenStreetMap의 온라인 타일을 이용합니다. 출처를 표시하고 대량 다운로드·오프라인 캐싱을 하지 않습니다. JS/CSS는 로컬 빌드 자산을 사용합니다. 준비물 체크 상태만 별도의 localStorage 키에 저장하며 기기 간 공유하지 않습니다.

## 확인

```sh
npm test
npm run build
npm run test:e2e
```

브라우저 테스트는 로컬 `.private/details.json`과 `.private/password.txt`가 필요하며, 기본적으로 macOS의 Google Chrome을 사용합니다. 다른 실행 파일은 `CHROME_PATH`로 지정할 수 있습니다. 공개 사이트를 열람하는 데 이 파일들은 필요하지 않습니다.

암호화·변조 검증, 배포물 원문 노출 검사, 비밀번호 실패/성공/취소, 페이지 이동과 잠금, 사진·지도 실패 대체 화면, 모바일 가로 넘침, 체크 저장, 하위 경로 호스팅을 확인합니다. `.private/forbidden.json`에는 배포물에 절대 포함되면 안 되는 원문 표식을 관리합니다. 로컬 비공개 원문이 없는 환경에서는 빌드가 구조적 검사만 수행한다고 명시합니다.

운영·전시 정보는 2026-09-24 기준 공식 안내를 참고했습니다. 식당 시간·평점은 엑셀 초안 값이므로 방문 전 확인하세요. 변경한 일정과 원래 선택 후보는 해당 일자에 설명되어 있습니다. 개인 예약 구매·변경은 수행하지 않았습니다.
